## 统一追踪方式

每条成绩必须能对应到以下信息：

1. **版本与源码**：发布版本、完整 `source_sha256` 和该次 `source_snapshot/`；版本号不能代替源码指纹。
2. **运行与模型**：`run_id`、规划模型、自动选中的候选及 `model_sha256`。目录名或候选名称不能代替模型指纹。
3. **数据划分与指标**：明确 validation 或 test，记录指标、行数、正确数和分数。索引中的 score 使用 0～1 的原始 accuracy；由已有分数与记录行数换算的正确数，另以 `correct_count_basis` 标明。
4. **证据**：原始配置、执行／调用日志、摘要、选择记录及重载核验结果。保留失败调用和历史费用，不能只收集成功候选。

`evidence_paths` 和 `model_artifact` 都是仓库根目录下的相对路径，方便在本地定位原始记录。`runs/`、模型、预测和完整日志被 Git 忽略，**不包含在公开源码仓库中**；索引是摘要，不是完整复现包，也不包含密钥、用户目录或原始样本。提交课程时须另行整理被报告成绩对应的模型、结果、源码快照和日志，保留原文件及其指纹。

## 记录新版本结果

在版本固定后，通过统一入口完成该版本的自主运行，并验证自动选模、模型重载和原始日志一致性，再添加新记录。写入当前版本成绩时，必须引用新运行实际记录的源码与模型指纹；不能复制历史行后仅改版本名。未取得的结果保持 `pending_not_run` 和空值，未宣布的 Unseen Task 指标也保持空值。

验证集成绩只能标为验证集成绩。已有测试结果仅作历史归档，不得进入后续方法选择或调参；正式结果应遵守课程要求的版本冻结、评估划分和自主执行规则。

本索引不声称费用已经满足课程的官方历史定价规则。学校价格计算值、未知用量预留和经核验的实际用量仍需在独立费用记录中区分；成绩存在不等于资源合规已经确认。
